# tmux + systemd для Debian и Ubuntu

Установщик tmux и пользовательской службы `tmux-systemd.service`. При загрузке сервера служба создаёт сессию `main`, к которой можно подключаться по SSH. Сессия продолжает работать после отключения SSH.

**tmux устанавливается непосредственно в операционную систему через APT. Docker для установки и работы не используется.**

Целевые системы: **Debian 12 и 13; Ubuntu 22.04, 24.04 и 26.04 LTS** с systemd. Требуется tmux 3.2+. Пакеты берутся из настроенных APT-репозиториев сервера. Нужен существующий пользователь с домашним каталогом и интерактивной оболочкой, доступ к APT и права root для установки. Контейнер без работающего systemd не подходит.

## Установка

Скачайте скрипт и запустите его:

```bash
curl -fsSL https://raw.githubusercontent.com/civisrom/tmux-systemd/main/install.sh -o install-tmux.sh && bash install-tmux.sh
```

Если `curl` отсутствует, установите его: `sudo apt-get update && sudo apt-get install -y curl ca-certificates`. В оболочке root команды выполняются без `sudo`.

Скрипт сам запрашивает повышение прав через `sudo`, если оно нужно. По умолчанию служба устанавливается для текущего пользователя; при запуске через `sudo` — для пользователя, вызвавшего `sudo`. При прямом запуске от root — для root. Для другого существующего пользователя:

```bash
bash install-tmux.sh --user USER
```

Замените `USER` именем пользователя. Новые учётные записи скрипт не создаёт. Перед запуском можно прочитать скачанный файл и посмотреть службу без установки:

```bash
less install-tmux.sh
bash install-tmux.sh --print-unit
```

Скрипт устанавливает отсутствующие пакеты `tmux` и `dbus-user-session`, при отсутствии пользовательской конфигурации создаёт настроенный `~/.tmux.conf` с RGB, записывает `~/.config/systemd/user/tmux-systemd.service` от имени выбранного пользователя, включает для него `loginctl enable-linger`, запускает пользовательский менеджер systemd и включает службу. Linger обеспечивает запуск при загрузке и работу после выхода пользователя. Общие настройки `logind` не меняются.

## Подключение

Войдите по SSH под пользователем, для которого установлена служба:

```bash
tmux -L systemd attach -t main
```

Отключиться от сессии, сохранив работающие программы: **Ctrl+b**, отпустить клавиши, затем **d**. Команда `exit` завершает оболочку в текущей панели.

```bash
tmux -L systemd list-sessions
tmux -N -L systemd new-session -A -s main
tmux -N -L systemd new-session -s work
```

Вторая команда подключается к `main` или создаёт её, если она закрыта. Третья создаёт дополнительную сессию `work`. Ключ `-N` не позволяет клиенту запустить сервер вне службы, если служба остановлена.

Служба использует сокет **`systemd`** в стандартном каталоге `/tmp/tmux-UID/`. Поэтому во всех командах нужен `-L systemd`. Обычная команда `tmux` обращается к отдельному серверу на сокете `default`. Если в вашей оболочке задан нестандартный `TMUX_TMPDIR`, используйте `TMUX_TMPDIR=/tmp tmux -L systemd …`.

## Управление службой

Команды выполняются под выбранным пользователем, без `sudo`:

```bash
systemctl --user status tmux-systemd.service
journalctl --user -u tmux-systemd.service -n 50 --no-pager
systemctl --user start tmux-systemd.service
systemctl --user stop tmux-systemd.service
systemctl --user restart tmux-systemd.service
```

**Остановка и перезапуск завершают все сессии и программы этой службы.** После перезагрузки машины или аварии tmux создаётся новая сессия: прежние процессы, содержимое памяти и история панелей не восстанавливаются. После аварийного завершения служба перезапускает сервер через 5 секунд; намеренное `tmux -L systemd kill-server` завершает его без автоматического запуска. Закрытие последней сессии оставляет сервер активным: новую сессию можно создать командой выше.

## Что улучшено в службе

- `Type=exec` и `tmux -D` запускают сервер без ухода в фон, поэтому systemd знает его PID. Отдельный PID-файл и угадывание PID не нужны.
- Отдельные имя службы и сокет позволяют использовать её рядом с ранее установленным `tmux.service` и обычным tmux.
- `ExecCondition` пропускает запуск, если сокет уже обслуживается другим сервером. Чужой сервер не останавливается.
- `ExecStartPost` ждёт готовности сокета и создаёт `main`, только если этой сессии нет. Клиентские команды используют `-N`; время запуска ограничено 20 секундами.
- `Restart=on-failure`, пауза 5 секунд и максимум 5 запусков за 60 секунд ограничивают повторяющиеся сбои.
- `KillMode=control-group` и `SendSIGHUP=yes` завершают процессы службы и уведомляют оболочки о закрытии терминала. `ExecStop=tmux kill-server` не используется.

Служба читает стандартную конфигурацию tmux выбранного пользователя; установщик сохраняет существующие настройки, а при их отсутствии создаёт описанный ниже шаблон. На каждом запуске службы `exit-empty` устанавливается в `off`. Настройки tmux, которые принудительно завершают сервер, или команды из конфигурации, ожидающие интерактивного ввода, могут помешать запуску.

Ограничения вроде `NoNewPrivileges=yes` намеренно не включены: они распространялись бы на команды внутри tmux и могли бы запретить привычное использование `sudo`. Сетевые порты служба не открывает.

## Повторная установка и существующий tmux

Повторно запустите скачанный установщик для обновления файла службы. Одинаковый файл не перезаписывается; отличающийся сохраняется рядом с расширением `.bak.XXXXXXXX`. Символические ссылки вместо файла службы, включая маску `/dev/null`, установщик не заменяет.

**Активная служба не перезапускается**, поэтому повторная установка не закрывает сессии. Изменения файла службы вступят в силу при следующем запуске. Для немедленного применения сначала завершите нужные задачи, затем явно перезапустите службу.

Существующие сессии на сокете `default` и прежний `tmux.service` не изменяются и не переносятся. Если прежняя служба больше не нужна, сначала закончите работу в её сессиях, затем отдельно отключите её. Автоматического переноса живых сессий между серверами tmux нет.

## Диагностика

При ошибке запуска проверьте журнал службы. После устранения причины и достижения лимита перезапусков:

```bash
systemctl --user reset-failed tmux-systemd.service
systemctl --user start tmux-systemd.service
```

Сообщение о занятом сокете означает, что tmux на `-L systemd` был запущен вне службы. Сначала подключитесь к нему и закончите работу. Только после этого завершите этот сервер и запустите службу. Установщик не завершает такие сессии автоматически.

При `Failed to connect to bus` войдите по SSH непосредственно под выбранным пользователем, а не через `su`. Проверьте наличие `dbus-user-session` и состояние пользовательского менеджера:

```bash
loginctl show-user "$(id -un)" -p Linger
sudo systemctl status "user@$(id -u).service"
```

## Удаление

Сначала завершите работу внутри сессий. Под владельцем службы выполните:

```bash
systemctl --user disable --now tmux-systemd.service
rm -- ~/.config/systemd/user/tmux-systemd.service
systemctl --user daemon-reload
```

Пакет tmux, его настройки и резервные копии службы сохраняются. Linger также сохраняется, поскольку от него могут зависеть другие пользовательские службы. Если он больше не нужен, отключите отдельно: `sudo loginctl disable-linger "$(id -un)"`.


## Как устроен tmux

**Сервер** tmux хранит сессии. **Сессия** содержит окна, **окно** — одну или несколько **панелей**. В панели работает отдельная оболочка или программа. **Клиент** — терминал, подключённый к сессии. Отключение клиента оставляет сервер и программы работать.

У каждого Linux-пользователя собственный сервер и права доступа. В этой установке сервер использует сокет `systemd`, а первая сессия называется `main`. Другой пользователь или другой сокет означает другой набор сессий.

Ниже команды shell запускаются из обычной оболочки выбранного пользователя. Внутри строки команд tmux (`Ctrl+b`, затем `:`) вводится только часть после `tmux -N -L systemd`. Например, вместо `tmux -N -L systemd list-sessions` введите `list-sessions`.

### Как читать команды и адреса

```text
tmux [общие параметры] команда [параметры команды] [аргументы]
```

В справочнике квадратные скобки означают необязательный элемент, многоточие — возможность повторения. Скобки из схемы вводить не нужно. Имена вроде `target-pane` нужно заменить реальной целью.

| Обозначение | Значение и пример |
|---|---|
| `session-name` | Имя сессии, например `main` или `work`. |
| `window-name` | Подпись окна, например `logs`. Это не обязательно его числовой индекс. |
| `target-session` | Имя или ID сессии. `=main` требует точного совпадения имени. |
| `target-window` | Адрес `сессия:окно`, например `main:0`, либо ID вида `@1`. |
| `target-pane` | Адрес `сессия:окно.панель`, например `main:0.1`, либо ID вида `%2`. |
| `target-client` | Имя подключённого терминала из `list-clients`, например `/dev/pts/3`. |
| `src-*` / `dst-*` | Источник и назначение операции. |
| `-t` | Цель команды; её тип зависит от команды. |
| `-s` | Часто источник или имя новой сессии; у параметров означает серверную область. |
| `-g` | Глобальная настройка соответствующей области, а не всех пользователей ОС. |
| `-F format` | Строка формата: `#{session_name}`, `#{window_index}`, `#{pane_id}` и т. п. |
| `-f filter` | Фильтр на основе формата tmux; глобальный `-f файл` имеет другое значение. |
| `shell-command` | Команда оболочки. Если нужны пробелы и операторы shell, заключите её в кавычки. |

По умолчанию окна и панели нумеруются с нуля. После пользовательской перенумерации реальные индексы могут отличаться. Перед адресной командой проверьте их через `list-windows` и `list-panes`. ID вида `%2` остаётся связан с панелью, пока она существует; числовая позиция может измениться.

## Повседневные команды с примерами

### Сессии и подключённые терминалы

| Команда | Что выполняет |
|---|---|
| `tmux -L systemd attach -t main` | Подключает терминал к `main`. |
| `tmux -N -L systemd new-session -A -s main` | Подключает к `main`, а при её отсутствии создаёт. Сама служба должна работать. |
| `tmux -N -L systemd new-session -d -s work` | Создаёт отдельную сессию `work` в фоне. |
| `tmux -N -L systemd attach -t work` | Подключает к `work`. |
| `tmux -N -L systemd attach -d -t main` | Подключает к `main` и отключает её остальные клиенты. Их SSH-соединения этим не закрываются. |
| `tmux -N -L systemd list-sessions` | Показывает сессии на сокете службы. |
| `tmux -N -L systemd has-session -t =work` | Проверяет наличие точно названной сессии `work`. |
| `tmux -N -L systemd rename-session -t work project` | Переименовывает `work` в `project` без перезапуска программ. |
| `tmux -N -L systemd list-clients` | Показывает подключённые терминалы. |
| `tmux -N -L systemd detach-client -t /dev/pts/3` | Отключает выбранный терминал; подставьте имя из `list-clients`. |
| `tmux -N -L systemd kill-session -t =project` | **Завершает** сессию `project` и окна, которые больше нигде не используются. |

При совместном подключении несколько клиентов могут управлять одной сессией. Для просмотра можно использовать `attach-session -r`; это режим клиента, а не отдельная система прав доступа к данным пользователя.

### Окна и панели

Ниже `main:0` и `main:0.0` — примеры адресов. Сначала посмотрите действующие индексы.

```bash
tmux -N -L systemd list-windows -t main
tmux -N -L systemd list-panes -a -F '#{session_name}:#{window_index}.#{pane_index} #{pane_id} #{pane_current_command}'
```

Первая команда показывает окна `main`. Вторая выводит адрес, устойчивый ID и имя программы для каждой панели сервера.

| Команда | Что выполняет |
|---|---|
| `tmux -N -L systemd new-window -t main -n logs` | Создаёт окно `logs`. |
| `tmux -N -L systemd new-window -t main -n monitor 'top'` | Создаёт окно и запускает в нём `top`. |
| `tmux -N -L systemd rename-window -t main:0 shell` | Переименовывает окно 0 в `shell`. |
| `tmux -N -L systemd select-window -t main:0` | Выбирает окно 0. |
| `tmux -N -L systemd split-window -h -t main:0` | Создаёт панели слева и справа. |
| `tmux -N -L systemd split-window -v -t main:0` | Создаёт панели сверху и снизу. |
| `tmux -N -L systemd split-window -h -l 30% -t main:0` | Выделяет новой панели 30% размера по направлению разделения. |
| `tmux -N -L systemd select-pane -t main:0.1` | Выбирает панель 1 окна 0. |
| `tmux -N -L systemd resize-pane -t main:0.0 -R 5` | Увеличивает панель вправо на 5 ячеек, если позволяет раскладка. |
| `tmux -N -L systemd resize-pane -Z -t main:0.0` | Увеличивает панель на всё окно; повторный вызов возвращает раскладку. |
| `tmux -N -L systemd select-layout -t main:0 tiled` | Располагает панели равномерной сеткой. |
| `tmux -N -L systemd select-layout -t main:0 even-horizontal` | Располагает панели рядом с равной шириной. |
| `tmux -N -L systemd select-layout -t main:0 even-vertical` | Располагает панели одна над другой с равной высотой. |
| `tmux -N -L systemd break-pane -s main:0.1 -t main: -n separate` | Выносит панель в отдельное окно. |
| `tmux -N -L systemd join-pane -h -s main:1.0 -t main:0.0` | Перемещает панель между окнами без повторного запуска программы. |
| `tmux -N -L systemd kill-pane -t main:0.1` | **Закрывает** указанную панель. |
| `tmux -N -L systemd kill-window -t main:1` | **Закрывает** окно 1 со всеми его панелями. |

### Завершившиеся программы и сохранённые ошибки

Шаблон включает `remain-on-exit failed`: если программа завершилась с ненулевым кодом, её панель остаётся, чтобы можно было прочитать ошибку. После нормального завершения с кодом 0 панель закрывается.

```bash
tmux -N -L systemd list-panes -a -F '#{pane_id} dead=#{pane_dead} status=#{pane_dead_status}'
tmux -N -L systemd respawn-pane -t %2
```

Первая команда показывает ID и статус панелей. Вторая повторяет прежнюю команду в уже завершившейся панели `%2`. Подставьте нужный ID. Чтобы вместо неё открыть оболочку:

```bash
tmux -N -L systemd respawn-pane -t %2 /bin/bash
```

`respawn-pane -k` сначала завершает работающую программу. Обычный `respawn-pane` без `-k` подходит для сохранённой панели с ошибкой и не убивает активный процесс.

В старых версиях tmux поле `pane_dead_status` может быть пустым после очень быстрого завершения программы, даже при `pane_dead=1`: обработка завершения и закрытие терминала происходят отдельно. Пустое поле не означает код 0. При завершении сигналом числовой код выхода также может отсутствовать. Это следует учитывать в сценариях автоматизации; связанное поведение разобрано в [исправлении самого tmux](https://github.com/tmux/tmux/pull/4841).

### Отправка ввода, копирование и файлы

```bash
tmux -N -L systemd send-keys -t main:0.0 -l 'pwd'
tmux -N -L systemd send-keys -t main:0.0 Enter
```

Первая строка вводит буквальный текст `pwd`. Вторая нажимает Enter, поэтому оболочка выполняет команду. Клавиша `C-c` означает Ctrl+C и обычно прерывает программу. Не направляйте ввод в панель, назначение которой не проверили.

| Команда | Что выполняет |
|---|---|
| `tmux -N -L systemd capture-pane -p -t main:0.0` | Печатает видимую область панели. |
| `tmux -N -L systemd capture-pane -p -S - -t main:0.0 > pane.txt` | Сохраняет доступную историю и экран в `pane.txt`. Перезаписывает файл. |
| `tmux -N -L systemd capture-pane -p -S -200 -t main:0.0` | Выводит историю начиная с 200 строк перед текущим экраном. |
| `tmux -N -L systemd set-buffer -b note 'Текст для вставки'` | Создаёт именованный буфер `note`. |
| `tmux -N -L systemd list-buffers` | Показывает буферы. |
| `tmux -N -L systemd show-buffer -b note` | Печатает содержимое `note`. |
| `tmux -N -L systemd paste-buffer -b note -t main:0.0` | Вставляет буфер в панель как ввод. |
| `tmux -N -L systemd save-buffer -b note note.txt` | Сохраняет буфер в файл. |
| `tmux -N -L systemd load-buffer -b note note.txt` | Загружает файл в буфер. |
| `tmux -N -L systemd delete-buffer -b note` | Удаляет буфер. |
| `tmux -N -L systemd clear-history -t main:0.0` | Удаляет историю прокрутки панели. |

Буферы tmux и буфер обмена вашего компьютера — разные механизмы. Передача в системный буфер зависит от терминала, OSC 52 и локальных настроек; наличие SSH само по себе такую передачу не гарантирует.

Чтобы записывать **новый** вывод панели в файл на сервере:

```bash
tmux -N -L systemd pipe-pane -o -t main:0.0 'umask 077; cat >> "$HOME/tmux-pane.log"'
tmux -N -L systemd pipe-pane -t main:0.0
```

Первая команда начинает запись с правами только для владельца нового файла; вторая её прекращает. Старые строки сохраняются через `capture-pane`. Лог может содержать показанные в терминале личные данные, поэтому его не следует добавлять в репозиторий.

## Горячие клавиши

Префикс — **Ctrl+b**: нажмите его, отпустите, затем нажмите указанную клавишу. Эти привязки стандартные; пользовательский конфиг может их изменить. Большие и маленькие буквы различаются.

| После Ctrl+b | Действие |
|---|---|
| `d` | Отключиться, оставив сессию работать. |
| `c` | Создать окно. |
| `n`, `p`, `l` | Следующее, предыдущее и ранее выбранное окно. |
| `0` … `9` | Перейти к окну по индексу. |
| `'` | Ввести индекс нужного окна. |
| `w` | Открыть выбор окон и сессий. |
| `s` | Открыть выбор сессии. |
| `$` | Переименовать сессию. |
| `,` | Переименовать окно. |
| `%` | Разделить окно на левую и правую панели. |
| `"` | Разделить окно на верхнюю и нижнюю панели. |
| Стрелки | Перейти в соседнюю панель. |
| `o`, `;` | Следующая панель и ранее активная панель. |
| `q` | Показать номера панелей; пока номера видны, цифрой можно выбрать панель. |
| `z` | Увеличить панель на всё окно или вернуть прежнее расположение. |
| Пробел | Следующая раскладка панелей. |
| `!` | Вынести панель в отдельное окно. |
| `{`, `}` | Поменять панель местами с предыдущей или следующей. |
| Ctrl+стрелка | Изменить размер панели на одну ячейку. |
| Alt+стрелка | Изменить размер панели на пять ячеек. |
| `x` | Запросить подтверждение закрытия панели. |
| `&` | Запросить подтверждение закрытия окна. |
| `[` | Открыть режим просмотра истории и копирования. |
| Page Up | Открыть историю и подняться на страницу. |
| `]` | Вставить последний буфер tmux. |
| `=` | Выбрать буфер для вставки. |
| `#` | Показать буферы. |
| `:` | Открыть строку команд tmux. |
| `?` | Показать клавиши и их описания. |
| `f` | Найти окно по строке. |
| `t` | Показать часы; `q` возвращает панель. |
| `D` | Выбрать клиент для отключения. |
| `(`, `)` | Предыдущая и следующая сессии. |
| `L` | Вернуться к ранее выбранной сессии. |
| `m`, `M` | Отметить панель и снять отметку. |
| `~` | История сообщений tmux. |
| Ctrl+b | Передать Ctrl+b приложению или вложенному tmux. |
| Ctrl+z | Приостановить клиент; вернуться через `fg` во внешней оболочке. |

В режиме копирования префикс перед каждым действием не нужен. `q` или Escape закрывает режим. В таблице Emacs обычно применяются Ctrl+Space для начала выделения и Alt+w для копирования; в таблице Vi — Space и Enter. Точную раскладку своего сервера можно посмотреть так:

```bash
tmux -N -L systemd show-options -gw mode-keys
tmux -N -L systemd list-keys -T copy-mode
tmux -N -L systemd list-keys -T copy-mode-vi
```

Мышь позволяет выбирать панели, изменять их размер и прокручивать историю. Чтобы выделять текст средствами самого терминала, обычно нужно удерживать Shift; это поведение зависит от терминального приложения.

## Создаваемая конфигурация и RGB

При отсутствии пользовательского конфига установщик создаёт **`~/.tmux.conf` с правами 600**. Существующий `.tmux.conf`, символическая ссылка на него или `~/.config/tmux/tmux.conf` имеют приоритет: установщик их сохраняет и не создаёт конкурирующую конфигурацию.

```bash
bash install-tmux.sh --print-config
```

Команда показывает шаблон без установки. Его параметры:

| Настройка | Значение и назначение |
|---|---|
| `destroy-unattached off` | Сохраняет сессии, даже если к ним не подключены клиенты. |
| `exit-unattached off` | Не завершает сервер из-за отсутствия подключённых клиентов. |
| `remain-on-exit failed` | Сохраняет панель с ошибкой программы для чтения вывода и повторного запуска. |
| `detach-on-destroy off` | При закрытии текущей сессии переключает клиента на другую доступную сессию. |
| `default-terminal 'tmux-256color'` | Задаёт `TERM` для программ внутри новых панелей. Запись terminfo поставляется пакетом `ncurses-base` целевых ОС. |
| `terminal-features ",xterm-256color:RGB,gnome*:RGB"` с `-as` | Добавляет поддержку RGB для указанных типов внешних терминалов. |
| `history-limit 100000` | Сохраняет до 100 000 строк истории панели; расход памяти зависит от числа панелей и их вывода. |
| `mouse on` | Включает управление tmux мышью. |
| `escape-time 50` | Даёт 50 мс для распознавания последовательности клавиш, начинающейся с Escape. |
| `focus-events on` | Передаёт события фокуса поддерживающим их приложениям. |

RGB-настройки в шаблоне записаны так:

```tmux
set -g default-terminal 'tmux-256color'
set -as terminal-features ",xterm-256color:RGB,gnome*:RGB"
```

Для отображения RGB ваш внешний терминал тоже должен поддерживать полноцветный вывод. Не задавайте `TERM=tmux-256color` глобально вне tmux: снаружи `TERM` должен описывать реальный терминал.

Посмотреть настройки текущего сервера и клиентского терминала:

```bash
tmux -N -L systemd show-options -gv default-terminal
tmux -N -L systemd show-options -s terminal-features
tmux -N -L systemd display-message -p '#{client_termname}: #{client_termfeatures}'
```

Последнюю команду выполняйте из подключённого клиента tmux. Пустые клиентские поля вне клиента не означают неисправность RGB.

Чтобы изменить настройки, отредактируйте файл и перечитайте его:

```bash
nano ~/.tmux.conf
tmux -N -L systemd source-file -n ~/.tmux.conf
tmux -N -L systemd source-file ~/.tmux.conf
```

`source-file -n` проверяет разбор файла без выполнения; он не гарантирует корректность всех значений параметров. Обычный `source-file` применяет команды. Для нового значения `default-terminal` откройте новую панель: окружение уже работающей оболочки автоматически не заменяется. При использовании только XDG-конфига подставьте его путь.

Полезные необязательные настройки — добавляйте их в свой файл, если они нужны:

```tmux
# Нумерация с единицы.
set -g base-index 1
setw -g pane-base-index 1

# Клавиши Vi в режиме копирования.
setw -g mode-keys vi

# Более короткая привязка перечитывания конфигурации.
bind r source-file ~/.tmux.conf \; display-message 'Конфигурация перечитана'
```

Эти дополнительные строки не входят в установочный шаблон. Изменение `base-index` само по себе не перенумеровывает уже существующие окна.

## Полная справка по управлению службой

Все команды `systemctl --user` ниже выполняются от владельца службы. Обычное `sudo systemctl --user` обращается к пользовательскому менеджеру root и не является способом управления службой другого пользователя.

| Команда | Что выполняет |
|---|---|
| `systemctl --user status tmux-systemd.service` | Показывает состояние, PID и последние сообщения. Для неактивной службы может вернуть ненулевой код. |
| `systemctl --user is-active tmux-systemd.service` | Проверяет, запущена ли служба сейчас. |
| `systemctl --user is-enabled tmux-systemd.service` | Проверяет включение автозапуска; это не проверка текущего запуска. |
| `systemctl --user start tmux-systemd.service` | Запускает остановленную службу. Активную не перезапускает. |
| `systemctl --user stop tmux-systemd.service` | **Останавливает сервер и его сессии**, сохраняя настройку автозапуска. |
| `systemctl --user restart tmux-systemd.service` | **Завершает текущие сессии** и запускает новый сервер с новой `main`. |
| `systemctl --user enable tmux-systemd.service` | Включает автозапуск, но не запускает немедленно. |
| `systemctl --user enable --now tmux-systemd.service` | Включает автозапуск и запускает службу. |
| `systemctl --user disable tmux-systemd.service` | Отключает автозапуск, оставляя текущую службу работать. |
| `systemctl --user disable --now tmux-systemd.service` | Отключает автозапуск и **завершает текущие сессии**. |
| `systemctl --user reset-failed tmux-systemd.service` | Сбрасывает состояние ошибки и счётчик ограничения запусков; сам сервер не запускает. |
| `systemctl --user daemon-reload` | Перечитывает файлы unit. Не перечитывает `.tmux.conf` и не перезапускает tmux. |
| `systemctl --user cat tmux-systemd.service` | Показывает файл службы и дополнительные drop-in настройки. |
| `systemctl --user show tmux-systemd.service -p MainPID -p ActiveState -p NRestarts` | Выводит выбранные поля состояния для диагностики. |
| `systemctl --user edit tmux-systemd.service` | Открывает редактор drop-in настроек. После правки параметры процесса применяются при следующем запуске службы. |
| `journalctl --user -u tmux-systemd.service -b --no-pager` | Показывает журнал службы текущей загрузки. |
| `journalctl --user -u tmux-systemd.service -f` | Следит за новыми сообщениями; Ctrl+C прекращает просмотр, сохраняя службу работающей. |
| `journalctl --user -u tmux-systemd.service --since '1 hour ago'` | Показывает сообщения за последний час. |
| `loginctl show-user "$(id -un)" -p Linger` | Проверяет работу пользовательского менеджера без входа в систему. |
| `sudo loginctl enable-linger "$(id -un)"` | Включает запуск пользовательского менеджера при загрузке и его сохранение после выхода. |

У службы нет `ExecReload`: команда `systemctl --user reload tmux-systemd.service` не предусмотрена. Для изменения параметров tmux используйте `source-file`, а для изменения unit — `daemon-reload` и, когда завершите работу в панелях, явный перезапуск.

Журнал systemd содержит события запуска, остановки и ошибки службы. Он не является полной записью содержимого панелей; для этого существуют `capture-pane` и `pipe-pane`.

## Общие параметры запуска tmux

Глобальные параметры ставятся **перед** именем команды. Например, `tmux -L systemd new-session -s work`: `-L` выбирает сокет сервера, а `-s` после `new-session` задаёт имя сессии.

| Параметр | Назначение |
|---|---|
| `-L имя` | Выбирает именованный сокет. Для этой службы — `-L systemd`. |
| `-S путь` | Выбирает сокет по полному пути; имеет приоритет над `-L`. |
| `-N` | Запрещает клиенту автоматически создавать сервер. Полезен при работе с сервером, которым управляет systemd. |
| `-f файл` | Выбирает конфигурацию при старте нового сервера. Не перечитывает конфиг уже работающего сервера. |
| `-D` | Запускает сервер без ухода в фон, отключая `exit-empty`. Используется службой; с ним нельзя передавать обычную команду tmux. |
| `-2` | Объявляет поддержку 256 цветов внешним терминалом; это не включение RGB. |
| `-T возможности` | Объявляет возможности клиентского терминала, например `RGB`. |
| `-u` | Включает вывод UTF-8 даже при другой локали. |
| `-C`, `-CC` | Режим управления для интеграций и программ; двойной `-C` дополнительно отключает эхо. Для обычного терминала не нужен. |
| `-c команда` | Выполняет команду через настроенную оболочку; используется в том числе для совместимости с login shell. |
| `-l` | Флаг совместимости с login shell; в описываемых версиях не меняет поведение. |
| `-v`, `-vv` | Включает отладочные журналы в текущем каталоге; двойной флаг дополнительно записывает терминальный вывод. Не используйте постоянно для обычной работы. |
| `-V` | Показывает версию tmux. |
| `-h` | Краткая справка в поддерживающих этот флаг версиях, включая 3.6. |

## Справочник всех встроенных команд

Ниже перечислены **все 90 команд из `tmux list-commands` версии 3.6**: имя, штатный псевдоним, синтаксис и объяснение. В Ubuntu 22.04 поставляется более ранний tmux; доступность команд и отдельных флагов определяется установленной версией. `clear-prompt-history`, `show-prompt-history` и `server-access` отсутствуют в tmux 3.2a. Даже у давно существующих команд новые флаги могли появиться позже.

Справку именно своего сервера можно получить без предположений о версии:

```bash
tmux -V
tmux list-commands
tmux list-commands split-window
man tmux
```

Синтаксис в блоках ниже начинается с имени команды. Для запуска из shell добавляйте `tmux -N -L systemd` перед ним, а необязательные части выбирайте по задаче. Исключение — самостоятельный `start-server`, который здесь описан для полноты и для службы не нужен.

### attach-session (attach)

```text
attach-session (attach) [-dErx] [-c working-directory] [-f flags] [-t target-session]
```

Подключает текущий терминал к существующей сессии. `-t` выбирает сессию; `-d` предварительно отключает её другие клиенты; `-r` включает просмотр без обычного ввода в панели. Сессия и её программы продолжают работать после отключения клиента.

### bind-key (bind)

```text
bind-key (bind) [-nr] [-T key-table] [-N note] key [command [argument ...]]
```

Назначает клавише команду tmux. `-T` выбирает таблицу клавиш; без него используется таблица `prefix`. `-n` назначает клавишу без префикса, `-r` разрешает повтор, `-N` добавляет описание. Назначение применяется немедленно; для сохранения запишите его в конфигурацию.

### break-pane (breakp)

```text
break-pane (breakp) [-abdP] [-F format] [-n window-name] [-s src-pane] [-t dst-window]
```

Выносит существующую панель в отдельное окно, сохраняя работающий процесс. `-s` задаёт исходную панель, `-t` — назначение, `-n` — имя окна, `-d` оставляет текущий выбор без переключения. Это перемещение, а не повторный запуск программы.

### capture-pane (capturep)

```text
capture-pane (capturep) [-aCeJMNpPqT] [-b buffer-name] [-E end-line] [-S start-line] [-t target-pane]
```

Копирует отображаемый текст панели и при необходимости историю в буфер tmux. `-p` печатает результат в stdout; `-S` и `-E` задают диапазон строк, `-S -` начинает с начала доступной истории. `-J` соединяет перенесённые строки, `-e` сохраняет управляющие последовательности оформления.

### choose-buffer

```text
choose-buffer [-NrZ] [-F format] [-f filter] [-K key-format] [-O sort-order] [-t target-pane] [template]
```

Открывает интерактивный список буферов вставки. Позволяет выбрать содержимое для вставки; `-t` определяет панель для интерфейса, `-F` — формат строки, `-f` — фильтр. В экранном интерфейсе `?` показывает действующие клавиши.

### choose-client

```text
choose-client [-NrZ] [-F format] [-f filter] [-K key-format] [-O sort-order] [-t target-pane] [template]
```

Показывает интерактивный список подключённых клиентов. Помогает найти терминал и выполнить действие над ним. `-F` меняет подпись, `-f` фильтрует клиентов; необязательный шаблон задаёт выполняемую при выборе команду.

### choose-tree

```text
choose-tree [-GNrswZ] [-F format] [-f filter] [-K key-format] [-O sort-order] [-t target-pane] [template]
```

Открывает дерево сессий, окон и панелей для переключения и управления. `-s` начинает с уровня сессий, `-w` — окон, `-Z` временно увеличивает панель интерфейса. Доступные действия отображаются по `?`.

### clear-history (clearhist)

```text
clear-history (clearhist) [-H] [-t target-pane]
```

Удаляет сохранённую историю прокрутки выбранной панели. Не останавливает её программу. Обычный экран и история оболочки — отдельные сущности; эта команда не заменяет очистку файлов истории Bash или Zsh.

### clear-prompt-history (clearphist)

```text
clear-prompt-history (clearphist) [-T prompt-type]
```

Очищает историю встроенных приглашений tmux, например строки команд. `-T` ограничивает тип приглашения. Это история самого tmux, а не команды, записанные оболочкой в файл истории.

### clock-mode

```text
clock-mode [-t target-pane]
```

Заменяет изображение выбранной панели часами до выхода из режима. Процесс внутри панели продолжает работать. `-t` выбирает панель; выйти можно клавишей `q`.

### command-prompt

```text
command-prompt [-1bFkliN] [-I inputs] [-p prompts] [-t target-client] [-T prompt-type] [template]
```

Открывает строку ввода внутри клиента tmux. `-p` задаёт текст приглашения, `-I` — начальное значение, шаблон определяет действие с введённым текстом. Используется в привязках для переименования и запросов параметров.

### confirm-before (confirm)

```text
confirm-before (confirm) [-by] [-c confirm-key] [-p prompt] [-t target-client] command
```

Запрашивает подтверждение перед выполнением команды tmux. `-p` задаёт текст вопроса; `-t` выбирает клиента. Флаг `-y` выполняет команду без вопроса, поэтому он не подходит для привязки, от которой ожидается подтверждение.

### copy-mode

```text
copy-mode [-deHMqSu] [-s src-pane] [-t target-pane]
```

Включает просмотр истории и выделение текста. `-u` сразу поднимается на страницу, `-e` позволяет выйти при достижении конца истории. Дальнейшие действия выполняются клавишами таблицы `copy-mode` или `copy-mode-vi`, либо через `send-keys -X`.

### customize-mode

```text
customize-mode [-NZ] [-F format] [-f filter] [-t target-pane]
```

Открывает интерактивное редактирование параметров и привязок клавиш. Удобно для знакомства с доступными настройками. Изменения действуют в текущем сервере; для воспроизведения после его перезапуска перенесите нужные команды в `.tmux.conf`.

### delete-buffer (deleteb)

```text
delete-buffer (deleteb) [-b buffer-name]
```

Удаляет один буфер вставки. `-b` выбирает его по имени; без имени используется подходящий буфер по умолчанию. Панели, программы и системный буфер обмена этой командой не уничтожаются.

### detach-client (detach)

```text
detach-client (detach) [-aP] [-E shell-command] [-s target-session] [-t target-client]
```

Отсоединяет терминал от tmux, сохраняя сессии. `-t` выбирает клиента, `-s` — клиентов сессии, `-a` исключает выбранного клиента и отключает остальных. Без дополнительных флагов это программный эквивалент `Ctrl+b`, затем `d`.

### display-menu (menu)

```text
display-menu (menu) [-MO] [-b border-lines] [-c target-client] [-C starting-choice] [-H selected-style] [-s style] [-S border-style] [-t target-pane] [-T title] [-x position] [-y position] name [key] [command] ...
```

Показывает меню из подписей, клавиш и команд tmux. `-T` задаёт заголовок, `-x` и `-y` — положение, `-t` — контекст панели. Предназначена прежде всего для пользовательских привязок и сценариев.

### display-message (display)

```text
display-message (display) [-aCIlNpv] [-c target-client] [-d delay] [-F format] [-t target-pane] [message]
```

Показывает сообщение в строке состояния. `-p` выводит результат в stdout, что удобно для сценариев; форматы вроде `#{pane_id}` подставляют сведения о выбранной панели. `-t` задаёт контекст, `-d` — длительность показа.

### display-popup (popup)

```text
display-popup (popup) [-BCEkN] [-b border-lines] [-c target-client] [-d start-directory] [-e environment] [-h height] [-s style] [-S border-style] [-t target-pane] [-T title] [-w width] [-x position] [-y position] [shell-command [argument ...]]
```

Открывает поверх клиента всплывающий терминал с командой. `-w` и `-h` задают размер, `-d` — рабочий каталог, `-E` закрывает окно после завершения команды, `-C` закрывает открытое всплывающее окно. Требуется подключённый клиент.

### display-panes (displayp)

```text
display-panes (displayp) [-bN] [-d duration] [-t target-client] [template]
```

Временно показывает номера панелей, чтобы выбрать нужную. `-d` задаёт длительность показа, `-t` — клиента. Это основа стандартной комбинации `Ctrl+b`, затем `q`.

### find-window (findw)

```text
find-window (findw) [-CiNrTZ] [-t target-pane] match-string
```

Ищет окна по заданной строке и открывает выбор результатов. `-N` ограничивает поиск именами, `-T` — заголовками, `-C` — содержимым; `-i` игнорирует регистр. Без уточняющих флагов используются стандартные области поиска версии tmux.

### has-session (has)

```text
has-session (has) [-t target-session]
```

Проверяет существование сессии. Возвращает код 0 при успехе и ненулевой при отсутствии; ничего не создаёт. Для точного имени используйте `-t =main`, чтобы исключить поиск по сокращению или шаблону.

### if-shell (if)

```text
if-shell (if) [-bF] [-t target-pane] shell-command command [command]
```

Выполняет одну из команд tmux в зависимости от успешности команды оболочки. `-F` вместо оболочки проверяет формат tmux, `-b` запускает проверку в фоне. Условия и вложенные команды требуют корректного экранирования.

### join-pane (joinp)

```text
join-pane (joinp) [-bdfhv] [-l size] [-s src-pane] [-t dst-pane]
```

Переносит существующую панель в другое окно и делит его пространство. `-s` задаёт источник, `-t` — получателя, `-h` размещает панели слева и справа, `-v` — сверху и снизу, `-l` задаёт размер. Процесс панели сохраняется.

### kill-pane (killp)

```text
kill-pane (killp) [-a] [-t target-pane]
```

**Закрывает панель вместе с работающей в ней программой.** `-t` выбирает панель; `-a` уничтожает остальные панели окна. Если панель последняя, может закрыться и её окно.

### kill-server

```text
kill-server
```

**Завершает весь выбранный сервер tmux: все его сессии, окна и панели.** Сокет выбирается глобальными `-L` или `-S`. Для штатной остановки установленной службы используйте `systemctl --user stop tmux-systemd.service`.

### kill-session

```text
kill-session [-aC] [-t target-session]
```

**Закрывает выбранную сессию.** Её окна уничтожаются, если больше не связаны с другими сессиями. `-a` закрывает все сессии, кроме указанной; `-C` очищает уведомления вместо уничтожения сессии.

### kill-window (killw)

```text
kill-window (killw) [-a] [-t target-window]
```

**Закрывает окно и его панели.** Если окно связано с несколькими сессиями, оно исчезнет из всех них. `-t` задаёт окно; `-a` закрывает остальные окна соответствующей сессии.

### last-pane (lastp)

```text
last-pane (lastp) [-deZ] [-t target-window]
```

Выбирает предыдущую активную панель окна. `-t` указывает окно, `-Z` сохраняет увеличение панели при переходе. Аналог стандартного переключения `Ctrl+b`, затем `;`.

### last-window (last)

```text
last-window (last) [-t target-session]
```

Возвращается к предыдущему выбранному окну в сессии. `-t` указывает сессию. Полезно для быстрого чередования двух окон без запоминания их номеров.

### link-window (linkw)

```text
link-window (linkw) [-abdk] [-s src-window] [-t dst-window]
```

Добавляет в другую сессию ссылку на уже существующее окно. Обе сессии видят одни и те же панели и процессы. `-s` выбирает исходное окно, `-t` — назначение; `-k` разрешает заменить занятое окно назначения и потому требует осторожности.

### list-buffers (lsb)

```text
list-buffers (lsb) [-F format] [-f filter]
```

Перечисляет буферы вставки, их имена и сведения о содержимом. `-F` задаёт формат вывода, `-f` — фильтр в версиях, где он поддерживается. Сам текст буфера можно получить через `show-buffer`.

### list-clients (lsc)

```text
list-clients (lsc) [-F format] [-f filter] [-t target-session]
```

Перечисляет терминалы, подключённые к серверу. `-t` ограничивает список клиентами сессии, `-F` определяет выводимые поля. Позволяет узнать имя клиента для адресного отключения.

### list-commands (lscm)

```text
list-commands (lscm) [-F format] [command]
```

Выводит все встроенные команды и их синтаксис для установленной версии tmux. Аргумент с именем команды сужает справку. Это надёжный способ проверить, поддерживается ли конкретная команда или флаг на данном сервере.

### list-keys (lsk)

```text
list-keys (lsk) [-1aN] [-P prefix-string] [-T key-table] [key]
```

Показывает действующие привязки. `-T` выбирает таблицу, например `prefix`, `copy-mode` или `copy-mode-vi`; `-N` показывает примечания к клавишам. Вывод отражает изменения из пользовательского конфига.

### list-panes (lsp)

```text
list-panes (lsp) [-as] [-F format] [-f filter] [-t target-window]
```

Перечисляет панели выбранного окна. `-s` расширяет список на сессию, `-a` — на весь сервер, `-F` задаёт поля: ID, PID, каталог, состояние процесса и другие. Используйте ID для устойчивого обращения к панели.

### list-sessions (ls)

```text
list-sessions (ls) [-F format] [-f filter]
```

Перечисляет сессии выбранного сервера. `-F` позволяет получить только нужные поля, например имя и количество окон. Наличие сервера на другом сокете или у другого пользователя на этот список не влияет.

### list-windows (lsw)

```text
list-windows (lsw) [-a] [-F format] [-f filter] [-t target-session]
```

Показывает окна сессии; `-a` перечисляет окна всех сессий. `-t` выбирает сессию, `-F` задаёт формат. Одно связанное окно может встречаться в нескольких сессиях.

### load-buffer (loadb)

```text
load-buffer (loadb) [-b buffer-name] [-t target-client] path
```

Загружает содержимое файла в буфер tmux. `-b` задаёт имя буфера; путь `-` читает stdin там, где он доступен. Затем данные можно вставить в панель командой `paste-buffer`.

### lock-client (lockc)

```text
lock-client (lockc) [-t target-client]
```

Блокирует выбранного клиента при помощи настроенной `lock-command`. Программы в панелях продолжают работать. Для фактической защиты требуется доступная и корректно настроенная программа блокировки.

### lock-server (lock)

```text
lock-server (lock)
```

Блокирует все подключённые клиенты выбранного сервера через `lock-command`. Не является остановкой tmux и не заменяет ограничения доступа к учётной записи и сокету.

### lock-session (locks)

```text
lock-session (locks) [-t target-session]
```

Блокирует клиентов выбранной сессии. `-t` задаёт сессию; работа её программ продолжается. Поведение снятия блокировки определяется `lock-command`.

### move-pane (movep)

```text
move-pane (movep) [-bdfhv] [-l size] [-s src-pane] [-t dst-pane]
```

Перемещает панель к указанной панели назначения с разделением пространства. По назначению соответствует `join-pane`: `-s` — источник, `-t` — назначение, `-h`/`-v` — ориентация. Процесс переносится вместе с панелью.

### move-window (movew)

```text
move-window (movew) [-abdkr] [-s src-window] [-t dst-window]
```

Перемещает окно в другую позицию или сессию. `-s` и `-t` задают источник и назначение; `-r` перенумеровывает окна. `-k` может уничтожить окно, занимающее место назначения.

### new-session (new)

```text
new-session (new) [-AdDEPX] [-c start-directory] [-e environment] [-F format] [-f flags] [-n window-name] [-s session-name] [-t target-session] [-x width] [-y height] [shell-command [argument ...]]
```

Создаёт сессию с окном и оболочкой либо указанной программой. `-s` задаёт имя, `-d` оставляет её в фоне, `-c` выбирает каталог. `-A` подключается к существующей сессии вместо ошибки; для такого подключения нужен терминал.

### new-window (neww)

```text
new-window (neww) [-abdkPS] [-c start-directory] [-e environment] [-F format] [-n window-name] [-t target-window] [shell-command [argument ...]]
```

Создаёт новое окно в выбранной сессии. `-n` задаёт имя, `-c` — каталог, `-d` не переключает текущий клиент. Можно передать команду вместо оболочки; `-P -F` позволяет получить ID созданного окна или панели.

### next-layout (nextl)

```text
next-layout (nextl) [-t target-window]
```

Применяет следующую стандартную раскладку панелей в окне. Программы сохраняются, меняется только расположение и размеры. `-t` выбирает окно.

### next-window (next)

```text
next-window (next) [-a] [-t target-session]
```

Выбирает следующее окно сессии по индексу. `-a` ограничивает переход окнами с уведомлением. `-t` указывает сессию.

### paste-buffer (pasteb)

```text
paste-buffer (pasteb) [-dpr] [-s separator] [-b buffer-name] [-t target-pane]
```

Вставляет буфер в выбранную панель как ввод. `-b` выбирает буфер, `-t` — панель, `-d` удаляет буфер после вставки, `-p` использует bracketed paste при поддержке приложением. Если текст содержит перевод строки, оболочка может выполнить команду.

### pipe-pane (pipep)

```text
pipe-pane (pipep) [-IOo] [-t target-pane] [shell-command]
```

Соединяет поток панели с внешней командой. Обычно используется для записи нового вывода в файл: `-O` задаёт направление из панели, `-I` — ввод в неё, `-o` открывает канал только при отсутствии существующего. Вызов без команды закрывает канал; старую историю он не записывает.

### previous-layout (prevl)

```text
previous-layout (prevl) [-t target-window]
```

Применяет предыдущую стандартную раскладку панелей. Меняет размещение, сохраняя процессы. `-t` выбирает окно.

### previous-window (prev)

```text
previous-window (prev) [-a] [-t target-session]
```

Выбирает предыдущее окно сессии. `-a` ограничивает переход окнами с уведомлением; `-t` задаёт сессию.

### refresh-client (refresh)

```text
refresh-client (refresh) [-cDlLRSU] [-A pane:state] [-B name:what:format] [-C XxY] [-f flags] [-r pane:report] [-t target-client] [adjustment]
```

Перерисовывает экран подключённого клиента и управляет его параметрами отображения. `-S` обновляет строку состояния. Остальные флаги используются в том числе управляющими клиентами для изменения размеров и отслеживания вывода.

### rename-session (rename)

```text
rename-session (rename) [-t target-session] new-name
```

Меняет имя существующей сессии, сохраняя окна и процессы. `-t` задаёт прежнее имя или ID, последний аргумент — новое имя. После переименования нужно использовать новое имя в командах подключения.

### rename-window (renamew)

```text
rename-window (renamew) [-t target-window] new-name
```

Меняет имя окна. `-t` выбирает окно, последний аргумент задаёт название. Для окна отключается автоматическое переименование; при необходимости его можно вновь включить настройкой `automatic-rename`.

### resize-pane (resizep)

```text
resize-pane (resizep) [-DLMRTUZ] [-x width] [-y height] [-t target-pane] [adjustment]
```

Изменяет размер панели. `-L`, `-R`, `-U`, `-D` выбирают направление и необязательное число ячеек; `-x`/`-y` задают размер. `-Z` переключает увеличение панели на всё окно без удаления соседей.

### resize-window (resizew)

```text
resize-window (resizew) [-aADLRU] [-x width] [-y height] [-t target-window] [adjustment]
```

Меняет размер всего окна в ячейках терминала. `-x` и `-y` задают ширину и высоту, направленные флаги изменяют их на указанную величину. Это отличается от изменения доли одной панели внутри окна.

### respawn-pane (respawnp)

```text
respawn-pane (respawnp) [-k] [-c start-directory] [-e environment] [-t target-pane] [shell-command [argument ...]]
```

Повторно запускает программу в завершившейся панели. Без новой команды повторяет прежнюю; с новой — запускает её. **`-k` предварительно убивает ещё работающую программу**, поэтому для панели с сохранённой ошибкой обычно достаточно команды без `-k`.

### respawn-window (respawnw)

```text
respawn-window (respawnw) [-k] [-c start-directory] [-e environment] [-t target-window] [shell-command [argument ...]]
```

Повторно запускает программу в окне и формирует его заново. Без новой команды повторяет прежнюю; `-k` разрешает принудительно завершить активные процессы. Используйте адресное `respawn-pane`, если нужна только одна панель.

### rotate-window (rotatew)

```text
rotate-window (rotatew) [-DUZ] [-t target-window]
```

Циклически перемещает панели между позициями раскладки. `-U` и `-D` выбирают направление. Содержимое и процессы панелей сохраняются; меняются занимаемые ими места.

### run-shell (run)

```text
run-shell (run) [-bCE] [-c start-directory] [-d delay] [-t target-pane] [shell-command]
```

Запускает команду оболочки из tmux. Обычно очередь команд ждёт завершения; `-b` запускает её асинхронно, `-d` задаёт задержку, `-c` — каталог в поддерживающих версиях. Это не создание постоянной интерактивной панели.

### save-buffer (saveb)

```text
save-buffer (saveb) [-a] [-b buffer-name] path
```

Сохраняет буфер tmux в файл; `-b` выбирает буфер, `-a` добавляет к существующему файлу, путь `-` направляет содержимое в stdout. Без `-a` существующий файл назначения перезаписывается.

### select-layout (selectl)

```text
select-layout (selectl) [-Enop] [-t target-pane] [layout-name]
```

Выбирает раскладку панелей: например `tiled`, `even-horizontal` или `even-vertical`. Можно использовать сохранённую строку `window_layout`. `-E` выравнивает размеры соседних панелей; `-n`/`-p` выбирают следующую/предыдущую раскладку.

### select-pane (selectp)

```text
select-pane (selectp) [-DdeLlMmRUZ] [-T title] [-t target-pane]
```

Делает панель активной. `-t` задаёт ID или адрес, `-L`/`-R`/`-U`/`-D` переходят по направлению. `-T` меняет заголовок, `-m` отмечает панель, `-M` снимает отметку.

### select-window (selectw)

```text
select-window (selectw) [-lnpT] [-t target-window]
```

Выбирает окно. `-t` задаёт адрес или ID; `-n`, `-p`, `-l` позволяют перейти к следующему, предыдущему или ранее активному окну. Данные в окнах не меняются.

### send-keys (send)

```text
send-keys (send) [-FHKlMRX] [-c target-client] [-N repeat-count] [-t target-pane] [key ...]
```

Передаёт клавиши в выбранную панель. `-l` трактует текст буквально, без распознавания названий клавиш; без него `Enter`, `C-c` и подобные имена обозначают нажатия. `-X` отправляет команду режиму копирования. Это реальный ввод в работающую программу.

### send-prefix

```text
send-prefix [-2] [-t target-pane]
```

Отправляет в панель саму клавишу префикса tmux. Полезно для вложенного tmux или программы, которой нужен `Ctrl+b`. `-2` использует второй префикс, если он настроен.

### server-access

```text
server-access [-adlrw] [-t target-pane] [user]
```

Управляет списком пользователей, допускаемых к серверу: просмотр, добавление, удаление, режим чтения или чтения/записи. Доступ также зависит от файловых прав на каталог и сокет. Для обычной установки с отдельным сервером каждого пользователя эта команда не требуется.

### set-buffer (setb)

```text
set-buffer (setb) [-aw] [-b buffer-name] [-n new-buffer-name] [-t target-client] [data]
```

Создаёт или меняет текст буфера вставки. `-b` выбирает имя, `-a` дописывает данные, `-n` переименовывает буфер. Значение передаётся аргументом: для чувствительного текста предпочтительнее загрузка через stdin, чтобы не помещать его в аргументы процесса.

### set-environment (setenv)

```text
set-environment (setenv) [-Fhgru] [-t target-session] variable [value]
```

Меняет окружение tmux для будущих процессов. `-g` выбирает глобальное окружение сервера, `-t` — окружение сессии, `-u` удаляет переменную. Уже работающие программы своё окружение автоматически не меняют.

### set-hook

```text
set-hook [-agpRuw] [-t target-pane] hook [command]
```

Назначает команду tmux на событие: создание сессии, завершение панели и другие. `-g` задаёт глобальный hook, `-u` удаляет, `-R` запускает его сейчас. Hook может выполнять команды, поэтому изменение следует проверять на отдельной сессии.

### set-option (set)

```text
set-option (set) [-aFgopqsuUw] [-t target-pane] option [value]
```

Меняет параметр tmux. `-s` выбирает серверный параметр, `-g` — глобальное значение, `-w` — окно, `-p` — панель, `-t` — цель. `-u` снимает локальное значение, `-a` добавляет к поддерживающему это значению; области параметров имеют значение.

### set-window-option (setw)

```text
set-window-option (setw) [-aFgoqu] [-t target-window] option [value]
```

Форма установки параметров окна, соответствующая `set-option -w`. `-g` изменяет глобальные значения для окон, `-t` задаёт конкретное окно, `-u` снимает локальную настройку. Псевдоним — `setw`.

### show-buffer (showb)

```text
show-buffer (showb) [-b buffer-name]
```

Выводит текст буфера вставки. `-b` выбирает именованный буфер; без него используется буфер по умолчанию. Вывод может содержать скопированные личные данные — учитывайте это при сохранении журналов.

### show-environment (showenv)

```text
show-environment (showenv) [-hgs] [-t target-session] [variable]
```

Показывает окружение сессии или, с `-g`, сервера. Можно указать имя одной переменной. `-s` формирует команды оболочки. Не публикуйте полный вывод без проверки: окружение может содержать секретные значения.

### show-hooks

```text
show-hooks [-gpw] [-t target-pane] [hook]
```

Показывает назначенные обработчики событий. `-g` выбирает глобальные hooks; необязательное имя ограничивает вывод одним обработчиком. Сочетания областей зависят от версии tmux.

### show-messages (showmsgs)

```text
show-messages (showmsgs) [-JT] [-t target-client]
```

Показывает историю сообщений клиента tmux. `-t` выбирает клиента; `-J` и `-T` позволяют получить диагностические сведения о заданиях и терминалах. Это не журнал всех команд, выполненных внутри оболочек.

### show-options (show)

```text
show-options (show) [-AgHpqsvw] [-t target-pane] [option]
```

Показывает действующие параметры соответствующей области. `-g` выбирает глобальные значения, `-s` — сервер, `-w` — окно, `-p` — панель. `-v` выводит только значение и удобен для проверок в сценариях.

### show-prompt-history (showphist)

```text
show-prompt-history (showphist) [-T prompt-type]
```

Показывает историю встроенных приглашений tmux. `-T` выбирает её тип. Содержимое отличается от истории команд оболочки и очищается через `clear-prompt-history`.

### show-window-options (showw)

```text
show-window-options (showw) [-gv] [-t target-window] [option]
```

Форма просмотра настроек окна, соответствующая `show-options -w`. `-g` показывает глобальные значения окон, `-t` выбирает окно, `-v` оставляет только значение. Псевдоним — `showw`.

### source-file (source)

```text
source-file (source) [-Fnqv] [-t target-pane] path ...
```

Читает файл как команды tmux и применяет их к текущему серверу. Сами сессии ради перечитывания не перезапускаются, но команды внутри файла могут их изменить или завершить. `-n` проверяет разбор без выполнения, `-q` разрешает отсутствие файла.

### split-window (splitw)

```text
split-window (splitw) [-bdefhIPvZ] [-c start-directory] [-e environment] [-F format] [-l size] [-t target-pane] [shell-command [argument ...]]
```

Создаёт новую панель в окне. `-h` делит пространство на левую и правую части, `-v` — на верхнюю и нижнюю; `-l` задаёт размер, например `30%`, `-c` — каталог, `-d` сохраняет фокус в прежней панели. Можно сразу запустить команду.

### start-server (start)

```text
start-server (start)
```

Запускает самостоятельный сервер tmux, если он ещё не работает. Для службы этого репозитория используйте `systemctl --user start`: самостоятельный сервер на её сокете будет обнаружен как конфликт. С глобальным `-N` создание нового сервера запрещено.

### suspend-client (suspendc)

```text
suspend-client (suspendc) [-t target-client]
```

Приостанавливает процесс подключённого клиента и возвращает управление внешней оболочке. Сервер и панели продолжают работу. Вернуться обычно можно командой `fg` в той же оболочке.

### swap-pane (swapp)

```text
swap-pane (swapp) [-dDUZ] [-s src-pane] [-t dst-pane]
```

Меняет две панели местами, сохраняя их процессы. `-s` задаёт источник, `-t` — назначение; `-U`/`-D` выбирают соседнюю панель. `-d` предотвращает автоматическое переключение активной панели.

### swap-window (swapw)

```text
swap-window (swapw) [-d] [-s src-window] [-t dst-window]
```

Меняет местами окна внутри одной сессии либо между сессиями. `-s` и `-t` задают окна, `-d` сохраняет текущий выбор. Содержимое окон и работающие программы сохраняются.

### switch-client (switchc)

```text
switch-client (switchc) [-ElnprZ] [-c target-client] [-t target-session] [-T key-table]
```

Переключает уже подключённого клиента на другую сессию. `-t` задаёт сессию, `-c` — клиента; `-n`, `-p`, `-l` выбирают следующую, предыдущую или прежнюю сессию. Обычно вызывается изнутри tmux.

### unbind-key (unbind)

```text
unbind-key (unbind) [-anq] [-T key-table] key
```

Удаляет привязку клавиши. `-T` выбирает таблицу, `-n` обращается к клавишам без префикса. **`-a` снимает все привязки выбранной таблицы**; для обычной правки укажите одну клавишу.

### unlink-window (unlinkw)

```text
unlink-window (unlinkw) [-k] [-t target-window]
```

Убирает связь окна с одной сессией. Если оно связано с другой сессией, процессы продолжают работать там. `-k` разрешает убрать последнюю связь, что приводит к уничтожению окна.

### wait-for (wait)

```text
wait-for (wait) [-L|-S|-U] channel
```

Синхронизирует сценарии через именованный канал сервера tmux. Без флага ждёт сигнал, `-S` отправляет сигнал; `-L` захватывает блокировку, `-U` освобождает её. Это средство координации команд, а не пауза фиксированной длительности.
